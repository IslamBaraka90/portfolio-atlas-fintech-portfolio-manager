## Scene plan

| Scene    | Spoken point                       | On-screen evidence                    | Expected state          | Actual take |
| -------- | ---------------------------------- | ------------------------------------- | ----------------------- | ----------- |
| Question | What decision does this enable?    | Portfolio screen or labeled plan      | Prerequisite state      | Pending     |
| Contract | What must the input mean?          | Records, units and clocks             | Explicit definition     | Pending     |
| Build    | How is the rule expressed?         | Task diff and diagram                 | Small verified step     | Pending     |
| Failure  | What does a bad input do?          | Named adversarial fixture             | Visible typed reason    | Pending     |

## Take preparation

Reset to the chapter's documented fixture and fake-clock time. Verify mode labels and privacy of displayed data. Use the real application outputs, not manually drawn success states. Capture the command and result associated with numerical claims.

## Learner materials

Link the exact start/end commits, setup instructions, fixtures, derivations, financial primary sources, relevant package reference and the next chapter's PRP. Do not publish internal absolute paths.

## Completion note

Record remaining limitations and any mismatch between the filmed take and committed behavior. Fix or explicitly describe material differences before publication.
