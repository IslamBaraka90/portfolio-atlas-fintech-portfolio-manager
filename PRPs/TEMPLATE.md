# PRP template — Chapter title

Status: planned. Stable chapter number: assign without renumbering existing lessons.

## Learner question and result

State the financial decision and the concrete backend/API/React result.

## Prerequisites

List completed chapter artifacts, data readiness, package exports and any explicit user-dependent release gate.

## Sources and conventions

Resolve catalog IDs and exact installed contracts. Record primary definitions, units, currency, clocks, missing-state policy, adjustment basis, numerical method and applicability.

## Scope

Name supported assets, use cases and states. Record extension seams and unsupported outcomes.

## Contracts

Describe entities, request/response/event schemas, state transitions, lineage, precision, revision and idempotency requirements.

## Tasks and commits

Use small tasks that each deliver a coherent behavior and test. Give every task a commit message in the form chapter-N task-M: do X to achieve Y.

## Backend and React outcomes

Name the use case, ports/adapters, routes, connected screen, accessibility and empty/loading/error/rejected states.

## Acceptance cases

Include an independent worked example, invalid inputs, equality boundaries, time/availability failures, replay and the relevant financial invariants.

## Validation execution

Specify what to run once implementation exists and what evidence to save. Never record planned checks as already passed.

## Video

Open with the decision, explain the contract, implement through Git checkpoints, break a boundary deliberately, prove the result and show the connected screen.

## Handoff

State the exact artifact passed to the next chapter. Update progress and stop after the requested work.
